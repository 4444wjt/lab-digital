# 实验室设备预约系统 · 数智化转型方案

**对象**：高校教学 / 科研实验室
**解决的问题**：设备预约靠微信群口头沟通，冲突要等到到场才发现，用完没有记录，利用率说不清。

本仓库包含**方案文档**与**可运行的最小 MVP**。MVP 只做「设备预约」一条主路径 —— 不是在痛点里挑最容易做的，而是挑**痛感最高、改动最小**的那个（见 `docs/01-业务挖掘.md` 第四节的排序）。

## 二、MVP 做了什么

**一条主路径：查空闲 → 提交预约 → 自动查冲突 → 审批 → 留痕 → 统计**

| 能力 | 说明 |
|---|---|
| **冲突自动检测** | 半开区间判断：上一场 11:00 结束、下一场 11:00 开始**不算冲突** |
| **冲突给建议** | 不只说"冲突了"，同时返回当天最近 3 个可约起点，点一下即填入 |
| **维护中设备** | 直接拒绝，不让人白跑 |
| **审批时二次校验** | 审批那一刻再查一次冲突（防止审批期间被别人抢先） |
| **开放时段校验** | 只允许 8:00–22:00，且不支持跨天 |
| **统计看板** | 每台设备的机时与次数、待审批数 |

**刻意不做**（避免 MVP 膨胀）：耗材领用、危化品管理、实验记录本、多级权限、移动端小程序。这些是二、三期，理由写在业务挖掘第四节。

## 三、跑起来

需要 **Python 3.11+**。

```bat
REM 1) 建虚拟环境
python -m venv .venv
.venv\Scripts\activate

REM 2) 装依赖
pip install -r requirements.txt

REM 3) 生成种子数据（8 台设备 / 5 条预约）
python -m app.seed --reset

REM 4) 启动
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8020
```

打开 **http://127.0.0.1:8020**

**演示冲突**：对 **D01（高效液相色谱仪）** 预约**明天 09:30–10:30** —— 与种子数据里 R001 的 09:00–11:00 冲突，会返回冲突详情 + 可约时段。

**重置演示数据**：`python -m app.seed --reset`

## 五、技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | **FastAPI + Uvicorn** | 三层：`store`（仓储）/ `service`（业务）/ `main`（路由） |
| 存储 | **JSON 文件** | MVP 不引入数据库；`store.py` 内加线程锁 + 原子写（先写 `.tmp` 再 replace） |
| 前端 | **React 18 + htm**（无构建步骤） | 运行时本地化，不依赖 CDN |
| 动效 | **GSAP 3.12** | 入场时间轴、hover 物理、鼠标光斑、数字滚动 |
| 设计 | GitHub Primer 深色令牌 | 无 Tailwind、无 UI 框架 |

**为什么不用数据库**：MVP 只有 8 台设备、几条预约。引入 Postgres 会让"跑起来"从 3 步变成 5 步，而这一步的成本对验证"冲突检测有没有用"毫无帮助。

**为什么不引 LangChain / 大模型**：这不是 AI 项目。预约冲突是确定性计算，用规则算比用模型猜可靠得多。

## 七、已知限制

1. **单机文件存储**：不支持并发多实例部署（JSON 文件会被互相覆盖）。生产需换数据库。
2. **无身份认证**：任何人都能提交与审批。MVP 阶段刻意省略，因为要验证的是"冲突检测有没有用"，不是权限模型。
3. **无扫码签到**：流程图里画的"扫码签到/签退"未实现，使用记录靠手动状态变更。
4. **设备状态靠人工标记**：没有对接设备开关机信号，"使用中"是按预约时间推算的。
5. **不做耗材与危化品**：那是另一个痛感维度，见 `docs/01-业务挖掘.md` 第四节。
