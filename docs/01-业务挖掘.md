# 实验室系统 · 业务挖掘

**对象**：高校教学/科研实验室（以单个学院的综合实验中心为样本）
**调研方式**：公开行业资料 + 高校实验室管理通行的作业方式还原
**产出目的**：为「数智化转型方案」确定要解决的真实问题，而不是先有系统再找场景

> **说明**：本文的痛点描述来自三家实验室信息化厂商公开的行业分析（盛元广通、白码、为乐信息）与高校实验室管理的通行做法，**不是本文作者独创的洞察**。文中的量化数字为**按典型规模估算**，已标注估算依据；落地前应以本校本院的真实盘点数据替换。

---

## 一、先划清边界：这里说的"实验室"是哪种

高校实验室至少有三类，痛点完全不同，不能混着做方案：

| 类型 | 典型特征 | 主要矛盾 | 本文是否覆盖 |
|---|---|---|---|
| **教学实验室** | 按课表开课、班级整建制进入、实验项目固定 | 排课冲突、耗材按班级备料、学生实验记录 | ✅ 覆盖 |
| **科研实验室（课题组）** | 人员流动大（研究生为主）、实验不规律、数据敏感 | 实验记录归属、试剂领用、设备抢用 | ✅ 覆盖 |
| **大型仪器共享平台** | 高价设备、跨院系开放、按时收费 | 预约冲突、机时计费、维保 | ✅ 覆盖（作为设备模块的一部分） |
| 检测/校准实验室（CMA/CNAS） | 出对外报告、要资质 | 质量体系、报告签发 | ❌ 不覆盖 |

**本文的样本设定**（用于后续所有估算）：

- **设备**：40 台（其中大型精密仪器 6 台）
- **实验房间**：5 间
- **在册使用者**：约 300 人（本科生 250 + 研究生 40 + 教师 10）
- **管理岗**：2 名专职管理员
- **年度耗材采购**：约 30 万元，分布在 15 个课题/课程经费下

## 二、现状：三条作业流，全靠人和纸

### 2.1 角色与他们的实际动作

| 角色 | 现在怎么做事 | 记录载体 |
|---|---|---|
| **学生** | 微信问老师/管理员"明天下午 X 设备空不空" → 得到口头答复 → 到点去用 | **没有记录**，全凭记忆和聊天记录 |
| **教师（课题组）** | 让学生自己去找管理员登记；耗材让学生去买，票据留着报销 | **纸质领用单 + 纸质发票** |
| **管理员** | 用一本纸质台账记设备借用；用 Excel 记耗材进出；安全检查前临时整理 | **纸质台账 + Excel** |

### 2.2 四条主流程的现状

**流程 A：设备预约**

```
学生微信问 → 管理员翻纸质本 / 凭记忆 → 口头答应或改期
→ 到实验室 → 发现有人在用 → 现场协调或白跑一趟
→ 使用完 → 管理员补记一行台账（经常漏记）
```

**流程 B：耗材/试剂领用**

```
学生告诉老师 → 老师批 → 学生找管理员领
→ 管理员在纸质单上写：品名 / 数量 / 领用人 / 日期
→ 库存靠管理员心里有数，或月底盘一次
→ 学期末按纸质单汇总，逐张对票据，归集到课题
```

**流程 C：实验记录**

```
学生用实验记录本手写 → 或直接记在自己电脑上的 Word
→ 毕业/离组时，记录随人走 → 下届学生重复踩坑
→ 需要查历史数据时，只能找当时的经手人
```

**流程 D：安全检查与数据上报**

```
接到检查通知 → 管理员翻纸质台账 + Excel
→ 补齐缺漏（补签、补日期）
→ 手工汇总成表格上报
→ 检查完，材料归档，下次再来一遍
```

## 三、痛点：按"痛的程度"排序，不按模块排序

### 痛点 1：设备预约冲突（最痛，且最容易验证）

**表现**

- 同一台设备被两个人约在同一时段，**双方到场才发现**
- 预约靠微信群消息，**消息会被刷掉**，后到的人看不到前面有人约了
- 设备坏了没人知道，下一组人到场才发现不能做

**后果**

- **单次白跑**：学生往返 + 等待，平均 40–60 分钟
- **估算频次**：按每周 3–5 次冲突计，**每学期约 60–80 次**
- **累计损失**：仅"白跑"一项，每学期 **40–80 小时**的学生时间

**为什么难自查**：冲突是偶发的、分散的，**没有记录就没有证据**，所以管理者自己也说不清到底冲突多少次。

**行业资料的原话**

> "学生线下找老师预约登记，多人预约同一台设备容易出现时间重叠，仪器出现故障后维保记录随手记在笔记本上，到定期检修阶段，很难梳理清楚过往故障频次、维修时间。"
> —— 白码《纸质台账拖垮科研?高校实验室数字化改造真实复盘》

### 痛点 2：耗材与危化品的"账实不符"

**表现**

- 领用只签一张纸，**领用时间、使用量、剩余存量不同步**
- 危化品没有双人登记（部分学校有制度但落不了地）
- 有效期没人盯，过期试剂到用的时候才发现

**后果**

- **安全检查前要临时补台账**，一次 1–2 天
- **学期末经费归集**：逐张票据核对归属课题，退单重补常见
- **一旦出事，无法追溯**（谁领的、什么时候、领了多少）

**行业资料的原话**

> "部分易制毒、危化试剂领用只签一张纸质单据，领用时间、使用量、剩余存量没法实时同步，遇到上级安全检查，临时整理台账要耗费大量时间。"
> —— 同上

### 痛点 3：实验记录随人流失

**表现**

- 记录分散在**手写本、个人电脑、微信文件**里
- 学生毕业、研究生离组，**记录就断了**
- 参数配置、失败经验没有沉淀，**下届重复试错**

**后果**

- 课题连续性被打断（**这个损失没法量化，但是最贵的**）
- 复现不出历史实验，只能重做

**行业资料的原话**

> "大量实验记录分散在学生电脑、笔记本中，学生毕业之后数据极易流失，造成科研工作断层。"
> —— 盛元广通《高校科研行业 LIMS 实验室管理解决方案》

### 痛点 4：没有数据，管理靠感觉

**表现**

- 设备利用率说不清（"好像那台离心机一直没人用"）
- 耗材消耗说不清（"这个学期买了多少手套"）
- 谁在用、用了多久、哪个课题花的钱，**都要临时查**

**后果**

- 采购决策没依据（**该买的没买，买来的闲置**）
- 上级要数据时临时拼，**拼出来的数还不一定对**

### 痛点 5（最容易被方案忽略）：人的抵触

**这一条不解决，前面四条都落不了地。**

**表现**

- 有多年经验的研究员**习惯手写记录**
- 老教师不熟悉线上操作
- 大家的第一反应是"**又要多填一个系统**"

**行业资料的原话**

> "不少从业多年的研究员已经习惯手写记录，觉得线上填报多了额外步骤，最开始抵触使用，只能简化日常填报字段，只保留必须登记关键信息，慢慢接受线上录入。"
> —— 白码《纸质台账拖垮科研?高校实验室数字化改造真实复盘》

**对方案的含义（重要）**

> **MVP 的字段必须少到"填一次不超过 30 秒"。**
> 不能一上来就做"设备档案 / 校准周期 / 维保计划 / 培训记录"全套 —— 那是给管理员看的，不是给一线用的。
> **先让一线觉得"比原来省事"，系统才活得下去。**

## 四、痛点排序：先做哪个

用两个维度打分：**痛感强度**（不解决会怎样）× **可落地性**（改动多少人的习惯）

| 痛点 | 痛感 | 可落地性 | 结论 |
|---|---|---|---|
| **设备预约冲突** | 高（天天发生，人人有感） | **高**（只改变"约"这一个动作） | 🥇 **MVP 首选** |
| 耗材领用 | 高（涉及安全与经费） | 中（要管理员与财务配合） | 🥈 二期 |
| 实验记录 | 中（当下不痛，长期很痛） | 低（改变科研人员习惯最难） | 🥉 三期 |
| 数据看板 | 低（是结果不是原因） | 高（有数据就能做） | 依赖前三个 |

**→ 所以 MVP 只做一件事：把「设备预约」从"微信口头"变成"在线可查、自动查冲突"。**

**这就是本方案的 MVP 范围。**

---

## 五、如果不动，会怎样

**不是"效率低一点"这种程度，而是三个具体后果：**

1. **每学期 40–80 小时的学生时间**消耗在白跑上，且**没人知道这件事发生了**（因为没记录）
2. **安全检查前的 1–2 天**永远要临时补台账，且**补出来的台账本身不可信**
3. **课题连续性**依靠个别学生的记忆，**人一走就断**

**这三条里，第 1 条是"看不见的浪费"，第 2 条是"合规风险"，第 3 条是"知识资产流失"。**

## 六、下一步要拿到的真实数据（落地前必须补）

本文的估算不能直接用于报价或方案承诺，落地前要盘点：

| 要盘的数据 | 从谁拿 | 用来做什么 |
|---|---|---|
| 设备台账（型号、购置年份、原值） | 资产管理处 | 报价里的"设备规模"、方案里的设备档案字段 |
| 近 12 个月实际预约次数与冲突次数 | 管理员台账 + 访谈 | 验证痛点 1 的量化假设 |
| 近 12 个月耗材采购明细与课题归属 | 财务 + 课题组 | 报价里的"耗材金额"、经费归集需求 |
| 现有信息化系统（是否已有资产系统/一卡通） | 信息中心 | 决定 MVP 要不要对接、还是先独立跑 |
| 管理员与骨干教师对"多填一个系统"的真实态度 | 访谈 | 决定 MVP 的字段数量 |

**⚠️ 这五项没拿到之前，任何"预计节省 X%"的说法都是猜的。**
